# Documentation Audit — InvoSmart

- **Date**: 2026-10-16
- **Commit**: 5b247e2 (branch `test/e2e-scenarios`)
- **Scope**: whole repo
- **Tier**: Medium, with a risk bump for security, data and audit (money + PII)
- **Required coverage**: 14/16 required purposes have a doc; 5/16 are adequate and current (9 partial, 2 missing)

## Summary

InvoSmart has more docs than most medium projects: 37 files, 10 ADRs, a PRD, architecture, database, RBAC, customer API and e2e testing docs. The newest docs are accurate. `docs/E2E_TESTING.md`, `docs/API.md` (matches `app/api/v1/*` and the generated `/api/openapi.json`) and `docs/WORKSPACE_RBAC.md` (role names and capability matrix match `lib/workspaces.ts:53-58`) all checked out against the code. The main problem is that most of the doc set was written once on 2026-08-11 and was not updated as workspaces, payments, reminders and the customer API shipped. ARCHITECTURE, PRD, DATABASE, CHANGELOG and three ADRs now describe an older system. The biggest risk is in operations. Configuration and deployment docs are wrong where it matters most: 27 env vars that app code reads are in neither README nor `.env.example`, and ARCHITECTURE says production migrations are automated when no pipeline runs them. Use the newer docs as written. Check everything dated 2026-08-11 or earlier against the code before acting on it.

## Findings

### F-01 · High · README API reference lists routes that don't exist and leaves out most routes
- **Check**: Q3 contract drift
- **Evidence**:
  - `README.md:220-221,227` list `/api/ai/composer`, `/api/ai/scanner` and `/api/telemetry`, but no `route.ts` exists for them (`app/api/ai/` contains `explain`, `invoice-insight`, `orchestrator`, `theme-suggest`).
  - The methods are wrong for `/api/admin/feature-flags` (README:222 says GET/POST; code exports GET/POST/PUT/DELETE), `/api/admin/uptime` (+POST), `/api/user/locale` (+PUT), `/api/invoices/templates/[id]` (+GET; the `instantiate` POST route has no row) and `/api/cron/uptime` (+POST).
  - Route groups that no doc covers: `/api/workspaces/*` (11 routes), `/api/opt/*` (11), `/api/receipts/*` (4), `/api/clients/*` (2), `/api/cron/reminders` and `reminder-delivery`, `/api/admin/audit-log(s)`, `/api/user/branding` and `theme`, `/api/payments` GET, `/api/openapi.json`, and others.
- **Impact**: Developers and agents will call or "fix" endpoints that don't exist, and won't find the workspace API.
- **Recommendation**: Don't keep a handwritten list of every route in README. Keep a short table by domain that links `docs/API.md` (canonical for the customer API) and `docs/WORKSPACE_RBAC.md` (workspace routes). Consider extending `lib/openapi.ts` if internal routes need a contract.

### F-02 · High · Env vars read by the code are missing from both env references, and the two references disagree
- **Check**: Q2 env drift, Q5 single source of truth
- **Evidence**:
  - 27 variables that non-test code reads are in neither `.env.example` nor README. Examples:
    - AI feature flags: `ENABLE_AI_ORCHESTRATION` (`lib/ai/orchestrator.ts`), `ENABLE_AI_OPTIMIZER_LOCAL` and `ENABLE_AI_OPTIMIZER_GLOBAL` (`app/api/opt/*`), `NEXT_PUBLIC_ENABLE_AI_OPTIMIZER`
    - Federation keys: `FEDERATION_ENDPOINTS`, `FEDERATION_KEY_ID`, `FEDERATION_PRIVATE_KEY`, `FEDERATION_PUBLIC_KEY`, `FEDERATION_TENANT_ID` (`lib/federation/bus.ts`)
    - Monitoring API access: `SENTRY_AUTH_TOKEN`, `SENTRY_ORG_SLUG`, `SENTRY_PROJECT_SLUG`, `POSTHOG_PROJECT_ID`, `POSTHOG_API_HOST` (`lib/ai/optimizer.ts`)
    - Other: `SLACK_WEBHOOK_URL` (`lib/team/slack.ts`), `DISCORD_WEBHOOK_URL`, `NEXT_PUBLIC_APP_URL` (used in payment links: `app/api/invoices/[id]/send-email/route.ts`), `UPTIME_MONITORED_ENDPOINTS`, `RECEIPT_DEFAULT_POSITION`, `RECEIPT_ALLOWED_POSITIONS`, `NEXT_PUBLIC_RUM_SAMPLE_RATE`.
  - `UPSTASH_REDIS_REST_*` and `KV_REST_API_*` are documented only in `docs/API.md:51-52`.
  - The `ENABLE_AI_*` flags and `AI_SA_MAX_AUTOPUBLISH_PER_DAY` are in README and AGENTS.md but not in `.env.example`.
  - The reverse gap: 13 variables are in `.env.example` but not README, including `STRIPE_SECRET_KEY`, `WORKSPACE_AUTH_MODE`, `WORKSPACE_NOTIFICATION_ENCRYPTION_KEY`, `INVOICE_SHARE_SECRET` and `FEDERATION_TOKEN_SECRET`.
  - Low: `CLOUDINARY_URL` and `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` are documented but never read. (`VERCEL_TOKEN` is used in CI, so it is fine.)
- **Impact**: `cp .env.example .env` produces an app where payment links, Slack alerts, federation and the optimizer's telemetry reads silently degrade. README omits security-relevant variables (`WORKSPACE_AUTH_MODE`).
- **Recommendation**: Make `.env.example` canonical, grouped and commented with required/optional and per-environment notes. Replace README's env section and AGENTS.md §4 with a link to it. Delete the variables nothing reads.

### F-03 · High · Deployment and migration procedure is undocumented, and ARCHITECTURE contradicts the pipeline
- **Check**: Missing required doc (DEPLOYMENT), Q3
- **Evidence**:
  - `docs/ARCHITECTURE.md:200` says production has "automated migrations (`npx prisma migrate deploy`)". No workflow, `vercel.json` or npm script runs `migrate deploy`. `release.yml`'s `deploy` job runs `prisma generate`, `build`, then `vercel deploy --prod` (around lines 162-195). `scripts/release-certification.mjs:259` only runs `migrate status`.
  - README:268-272 says GitHub Actions run "formatting" (there is no format step) and that the "Vercel integration handles preview deployments". The actual deploy is tag-triggered (`if: startsWith(github.ref, 'refs/tags/v')`), and the local clone has no tags.
  - Rollback is documented only for the workspace migration (`docs/WORKSPACE_RBAC.md:80`).
  - `docs/RUNBOOK_RELEASE_CERTIFICATION.md` covers verification gates well but not the release order.
- **Impact**: A release can ship schema-dependent code before its migration has run. Nobody can say which step is automatic.
- **Recommendation**: Add `docs/DEPLOYMENT.md`, covering environments, tag/release flow, migration step and order, rollback, the crons, and post-deploy checks. Link the certification runbook from it rather than duplicating it, and fix ARCHITECTURE §10 and README "Deployment".

### F-05 · Medium · Three ADRs are contradicted by the code and still marked Accepted, and recent decisions have no ADR
